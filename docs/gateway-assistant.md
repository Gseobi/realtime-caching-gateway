# CRM 지식 어시스턴트

공유 테넌트 모드에서 어시스턴트를 명시적으로 활성화하면
`POST /v1/api/crm/conversations/{id}/assistant`로 질문을 보낼 수 있다.
요청 본문은 `{"question":"환불 신청 기한은 언제인가요?"}` 형태다.
호출자는 JWT에 `assistant.answer`와 `knowledge.read` 스코프를 모두 보유하고,
해당 테넌트의 CRM 대화에 접근할 수 있어야 한다. 답변은 대화 이력에 자동 저장되지 않는다.

## 자체 호스팅 모델 설정

```yaml
gateway:
  assistant:
    enabled: true
    origin: http://127.0.0.1:11434
    chat-model: "your-chat-model:version"
    embedding-model: "your-embedding-model:version"
    embedding-dimensions: 768
    max-concurrency: 2
    timeout-seconds: 15
```

기본값은 비활성이다. 활성화하려면 JWT 인증과 공유 테넌트 저장소가 필요하다.
예제의 모델 식별자와 차원은 자체 Ollama 서버의 실제 값으로 교체한다. 모델 식별자는 API
응답과 일치해야 한다. 게이트웨이는 HTTPS 또는 루프백 HTTP만 허용하고 리디렉션을 따르지 않는다.
승인된 문서 일부가 모델 서버로 전송되므로 신뢰하는 자체 서버를 지정한다.

## 검색과 응답 경계

- PostgreSQL 어휘 검색으로 테넌트와 문서 ACL을 적용해 후보를 최대 8개 가져온다.
  질문과 후보를 요청 시 임베딩으로 변환해 코사인 유사도로 재정렬하고 최대 3개를 생성에 사용한다.
  영구 벡터 인덱스는 사용하지 않는다.
- 모델 호출 전에 문서의 접근권한과 리비전을 다시 확인한다. 생성 후에는 대화 접근권한과
  모델에 제공한 모든 출처를 재확인한다. 추론 중 문서가 삭제되거나 권한이 바뀌면 답변을 폐기한다.
- 게이트웨이는 질문 길이, 후보·출처 수, 생성 토큰, 응답 크기와 인스턴스당 동시 요청을
  제한한다. 모델 호출은 JWT 만료와 설정된 시간 제한 중 먼저 도달하는 시각을 사용한다.
- 성공 응답은 `GROUNDED`와 답변, 모델 식별자, 문서 리비전 및 청크 출처를 반환한다.
  근거 부족, 모델 오류, 시간 초과, 동시 처리 한도 도달 시 `ABSTAINED`와 사유를 반환한다.
  출처 검증은 모델이 받은 문서와 실제 인용의 일치를 확인한다. 문장별 사실성은 출시 품질 검증 범위다.

PostgreSQL과 로컬 Ollama 호환 HTTP 테스트 서버를 사용해 정상 인용, 테넌트·문서 권한,
추론 중 삭제, 범위 밖 인용, 시간 초과 및 비활성화 동작을 검증한다.
실제 모델 품질과 배포 환경의 부하·추적·운영 승인 경로는 출시 검증 단계에 남아 있다.
