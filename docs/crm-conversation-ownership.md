# CRM 대화 소유권

공유 테넌트 모드에서 `crm.manage` scope를 가진 담당자가
`POST /v1/api/crm/conversations`에 `{customerId,contactId,participants}`를 보내면 201과 `conversationId`를 받는다. 참가자는 발급자가 보장하는 JWT sub 목록이다. 담당자는 요청 본문이 아니라 현재 JWT의 sub다. 고객과 연락처는 테넌트 키로 저장되며 기존 고객을 다른 담당자가 가져가거나 기존 연락처를 다른 고객에 붙일 수 없다. 모든 연관 행은 한 트랜잭션에서 기록한다. 외부 PII나 모델 제공자에 의존하지 않는다.

서버가 발급한 `crm_<UUID>` 대화는 해당 테넌트의 담당자와 참여자만 읽거나 쓸 수 있다. 기존 메시지 read/write scope도 별도로 필요하다. 목록, 복합 커서 이력, 메타, 쓰기 모두 이 검사를 사용한다. 이 모양의 ID는 공유 모드에서 예약이며 미등록 ID도 거부한다. 기존 공유 테넌트 DB에서 예약 패턴과 충돌하는 ID가 있는지 배포 전에 확인한다. 레거시 모드와 나머지 기존 대화 ID는 기존 동작을 유지한다. 담당자 변경·참여자 제거·기존 대화 이관은 이번에 제공하지 않는다.

v5 마이그레이션이 필요하다. HTTP 통합 검증은 담당자와 참가자의 성공, 같은 테넌트 비참여자의 이력·메타·쓰기 거부, 다른 테넌트의 접근 거부, 고객 탈취 거부를 포함한다.
