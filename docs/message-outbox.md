# 메시지 Outbox와 로컬 수신함

공유 테넌트 메시지 저장은 v4 스키마를 요구한다. 메시지·재시도 영수증·대화 상태와 `message.created`를 하나의 DB 트랜잭션에 기록한다. 이벤트는 테넌트와 메시지 참조만 포함하고 본문은 복제하지 않는다. 레거시 파티션은 종전과 같이 Outbox를 만들지 않는다.

선택적으로 `gateway.outbox.relay.enabled=true`, `gateway.outbox.relay.tenants=team-a,team-b`로 로컬 릴레이를 실행한다. 관리자가 허용한 테넌트만 처리한다. PostgreSQL의 행 잠금과 만료 리스로 병렬 작업을 분리하며, 만료되거나 교체된 리스로 완료할 수 없다. 수신함 insert와 완료 표시는 하나의 트랜잭션이다. 실패하면 제한된 지수 지연으로 재시도하고, 작업자가 종료돼도 리스가 만료되면 다시 받을 수 있다.

수신함은 `(tenant_id,event_id)` 고유 키로 중복 수신을 방지한다. 소비자는 이 키로 Outbox 행을 조인해 이벤트 메타데이터를 읽는다. 운영 재처리는 작업자를 중지한 상태에서 대상 테넌트와 이벤트를 확인하고 그 행의 `delivered_at`을 NULL로 되돌리는 방식이다. 수신함에 이미 있는 이벤트를 재처리해도 행이 중복되지 않는다. 이 경계는 PostgreSQL 로컬 전달까지이며 외부 시스템 부수효과의 exactly-once나 전체 이벤트 순서를 보장하지 않는다. 실제 CRM 자동화나 색인 소비자, 메시지 삭제 이벤트는 별도 연결 작업이다. Pub/Sub은 실시간 알림 전용이다.
