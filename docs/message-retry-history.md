# 메시지 멱등 재시도와 이력 페이지

메시지 POST에 선택적으로 `Idempotency-Key`(1–128 ASCII 영숫자 또는 `._~-`)를 전달한다. 키는 테넌트별 메시지 생성 작업 안에서 유일하다. 같은 요청을 다시 보내면 첫 성공과 같은 HTTP 200을 반환하고 DB·캐시·Pub/Sub을 중복 갱신하지 않는다. 같은 키를 다른 요청에 쓰면 409다. 헤더가 없으면 기존 동작을 유지한다.

요청의 경로 대화 ID, 메시지 ID, 발신자, 타입, 본문, 메타데이터 문자열과 명시한 시각을 길이 구분해 SHA-256으로 해시한다. 자동 생성 시각은 해시하지 않는다. 영수증·메시지·대화 상태는 한 트랜잭션에서 저장한다. 기본 READ COMMITTED에서 경합한 재시도는 고유 키의 결과를 기다린 뒤 다음 SQL 문에서 영수증을 조회한다. 강한 격리 수준에서 직렬화 실패가 발생하면 호출자가 트랜잭션 전체를 재시도해야 한다. 영수증 TTL은 이번 변경에 포함하지 않았다.

`GET /v1/api/conversations/{conversationId}/messages/history?limit=50&cursor=...` 는 `{messages, nextCursor}`를 반환한다. 첫 조회에는 cursor를 생략하고 마지막 페이지에서 nextCursor는 null이다. 조회는 PostgreSQL의 `(sent_at, message_id)` 내림차순을 사용한다. 토큰은 버전이 있는 탐색 위치이며 서명이나 권한 증명으로 사용하지 않는다. 토큰의 테넌트와 대화를 검사하며 SQL에는 항상 현재 인증 범위를 별도로 적용한다. 페이지 간 일관된 스냅샷은 보장하지 않는다. 기존 GET 응답과 시간 필터는 그대로다.

DB에 v3 마이그레이션을 적용한 뒤 멱등 헤더를 사용한다. 고객/연락처/담당자 소유권 모델은 아직 연결되지 않아 설계 2번 전체를 완료로 집계하지 않는다.
